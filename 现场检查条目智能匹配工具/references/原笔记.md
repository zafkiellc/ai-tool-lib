## 三-续、迭代功能实现要点（2026-08 多轮沉淀）
> 改代码前必读，避坑。

1. **视频督导模式 `video_mode`**：`_random_fill(manual, target, max_per_cat, video_mode)`，为真时强制 `target=2, max_per_cat=2`，候选池只留 `_VIDEO_KW` 命中项（六步法/五步法/服务流程/服务动作/开口营销/微笑/问候/迎客/送别/引车/双手/唱收/唱付/引导/推介/自助加油/洗车）。**刻意排除**裸「收银」（误命中资金安全）和泛化「增值服务」。前端 `#chk-video` 紫色复选框。
2. **固定/锁定条目 `fixed`（📌）**：自动补足条目卡片有 📍/📌 切换；一旦确定匹配项（`r.picked` 被设置）自动 `fixed=true`。`fetchFill()` 把 `fixed` 项随 `manual` 发后端，再次补足只补未固定空缺；`fillSig` 缓存键加入锁定集合。
3. **上传接口防丢数据**：`_random_upload` 旧 bug 是 `seen` 集合误把已有条目算进去致 append 变 replace（108→2）；修复为 `merged_norms` 只去重新条目重复，`base = existing_user_items + merged`。
4. **随机补足真随机**：后端 `random.shuffle` 每调不同，是真随机；「每次一样」是前端 `fillSig` 缓存错觉，手动点补足按钮会真重排。验证：连续 4 次结果应全异。
5. **DeepSeek 模型名显式校验**：`DeepSeek-v4-flash` 非官方（仅 `deepseek-chat`/`deepseek-reasoner`）；端点无此模型返回 400/404 或空响应，旧码静默吞成 null。`_call_llm` 对 HTTP 非 200 抛 `ValueError("HTTP <码>：<响应体前400字>")`；非 JSON 把模型原文带进 reason。前端 `testAiConnection` 显式展示原因。
6. **删除彻底性**：自动补足条目删除执行 `supplements.filter(s=>s.id!==r.id)` 后 `addRecordsFromText()` 重建，不会复活（再次抽到相同文本是新对象，属正常随机）。
7. **实例端口锁**：端口 8720/8721，旧 server 不退出双击仍加载旧代码 → 改前先 `taskkill /f /pid <旧PID>` 重启验证。
8. **验证三件套**：`py_compile(server.py, ai_lib.py)` + `node --check inspector_matcher.html`（HTML 内嵌 JS 语法）+ 起真实服务 urllib 实测（条数/已删分类不再出现/补足多次全异/视频督导=2/GBK 上传不丢数据）。

## 七、常见坑速查
| 现象 | 真因 | 修复 |
|---|---|---|
| 随机补足每次一样 | 前端 `fillSig` 缓存 | 手动点补足重排；查缓存键 |
| DeepSeek 返回 null | 模型名非官方被拒，旧码静默吞 | `_call_llm` 显式抛错带响应体 + 前端暴露原因 |
| 上传后数据变少 | `seen` 误跳已有条目 | `merged_norms` 只去重新条目重复 |
| 改动不生效 | 旧 server 占端口 | `taskkill` 旧 PID 重启 |
| CSV 中文乱码 | 文件 GBK/GB18030 | `_decode_text` 自动识别 |
| 自动补足删不掉 | 误以为重建复活 | 确认 `filter`+`addRecordsFromText` 路径 |
